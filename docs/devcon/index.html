Why Build This?

The friction was obvious

One checkout, too many experiments

Branch switching, stashing, and dirty state make parallel work fragile.

AI editors often hide the engine

Great UX, but the actual tool gets abstracted away behind a wrapper.

Parallelism becomes chaos

If every agent shares the same workspace, they trip over each other fast.

The target state

Parallel, isolated, steerable AI work across one or many repos

  • Each agent gets a clean working directory.
  • You keep the real terminal and can intervene anytime.
  • The desktop app adds review, memory, search, previews, and PR flow around it.

How I Developed Manifold

Manifold was built with the same kind of workflow it now supports

  • I start with intent, not with a giant vague coding prompt.
  • I ask the AI to absorb the relevant context material before I ask it for solutions.
  • I use the AI to think with me before I ask it to implement.
  • The human part is still the hard part: product judgment, evaluation, sequencing, and taste.

Start with intent

Have at least a general idea of what the feature, system, or change is supposed to do.

Load context first

Ask AI to get familiar with docs, code, and any existing material before it starts proposing changes.

Force structure

Make the AI produce a specification and an implementation plan instead of jumping straight into code.

Close the loop

Implement, test the result, then refactor against explicit rules like max LOC and code-organization constraints.

Architecture

Electron is a pragmatic fit for local orchestration

Main process

Owns the real system work

  • PTY processes
  • Git and worktree operations
  • Memory, search, settings
  • Provisioning and deploy integrations
Preload

Keeps the boundary tight

  • Whitelisted IPC channels
  • Context isolation
  • Bridge, not business logic
Renderer

Delivers the desktop experience

  • Dockable panes
  • Editors, previews, status
  • Developer View and Simple View
