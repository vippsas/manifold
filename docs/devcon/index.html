Why This Talk

The bottleneck moved

Typing became cheaper

Agents can now draft, refactor, and scaffold faster than the old manual loop.

Waiting became visible

An agent response can take between 15 and 45 minutes, so serial work wastes time fast.

Judgment matters more

The hard parts are now scoping, verifying, steering, reviewing, and deciding what to build next.

The new target state

A workflow that keeps moving while agents think, test, and return

  • Parallel tasks instead of one long blocking interaction
  • Explicit tests, screenshots, and success criteria instead of hope
  • A toolkit for permissions, templates, review, and context

Tool Choice

Claude Code and Codex both earn a place in my workflow

  • Claude Code is strong when I want terminal-native steering, repo-aware instructions, and tight interaction.
  • Codex is strong when I want delegated work, isolated execution, and PR-sized tasks running in the background.
  • The point is not brand loyalty. The point is matching the operating mode to the task.

Claude Code

Great when I want an interactive terminal partner that I can steer in real time.

Codex

Great when I want a task to run independently in the background and come back as a reviewable, issue-shaped unit.

Same habits win

Both tools benefit from structure, context, tests, and explicit success criteria.

The real comparison

The best question is not “which model is best?” It is “which operating mode fits this job?”

Working principle

Anthropic and OpenAI both converge on the same pattern: explore, plan, implement, verify, then refine, while keeping the context window focused enough that the agent stays on track.

My Main Workflow About Agentic Coding

A repeatable loop beats one giant prompt

01

Intent

Start with a rough intent, not a vague request for magic.

02

Context

Load only the relevant docs, files, markdown notes, and patterns first. More context is not always better.

03

Discussion

Tell the agent your thoughts, then ask for its thoughts before coding.

04

Specification

Force the work into a markdown spec so the change becomes concrete and reusable.

05

Plan

If the task is non-trivial, get an implementation plan before edits start.

06

Implementation

Let the agent implement the plan instead of improvising inside one long thread.

07

Verification

Run tests, commands, screenshots, or previews so the agent can check itself.

08

Refactor

Use explicit rules like max LOC, smaller functions, better file boundaries, and start fresh if the session has drifted.

Security And Speed

Permissions and allowlists shape flow

  • Approval prompts are good security when trust is low and scope is unclear.
  • But constant prompts slow development and eventually train you to stop paying attention.
  • Claude Code supports auto mode, command allowlists, and sandboxing to reduce this drag.
  • A good `.claude/settings.json` is not setup trivia. It is part of the workflow design.
  • If the allowlist is too narrow, you waste the day approving harmless commands. If it is too broad, security becomes theater.
  • The goal is not zero friction. The goal is the right friction in the right places.

Durable Context

Memory, markdown, and skills make the workflow compound

  • The live context window fills up fast, so keeping it focused is now a real engineering concern.
  • Stable instructions belong in markdown files like CLAUDE.md and AGENTS.md, not repeated inside every prompt.
  • Skills are reusable workflow knowledge: one good skill helps many times, keeps sessions leaner, and reduces repeated explanation.

Keep the live context lean

If a session gets cluttered or starts drifting, split the task or start fresh instead of arguing with stale context.

Cross-session memory matters

Agents lose context between sessions. Memory that persists across conversations prevents repeated explanation.

Markdown and skills offload pressure

Put stable instructions into files and skills so the agent does not have to relearn the same rules every session.

Starting Well Matters

Repo templates are leverage

  • A good template turns best practices into a starting point instead of a checklist.
  • GitHub templates let you create new repositories with the same structure, files, and optionally branches.
  • In my own workflow, provisioners are the mechanism and templates are the substance.
  • Templates encode taste: stack, testing defaults, deployment shape, docs, and structure.
  • They lower the cost of the next idea enough that building becomes easier than debating.

Decision Making

Build first before you invite everyone into a meeting

  • AI makes first drafts and prototypes dramatically cheaper than they used to be.
  • If I can build a thin slice today, I would rather show that than debate it abstractly for an hour.
  • Prototyping earlier reduces rework and creates alignment before assumptions calcify.
  • The prototype does not need to be final. It just needs to make the discussion concrete.

Before

Speculation, interpretation gaps, and the loudest voice in the room.

Build

A rough prototype, a working screen, or one real flow that people can react to.

After

Faster decisions because the team is now discussing something concrete.

Skill Curve

Agentic AI needs a lot of practice

  • There is a real learning curve, even when the tooling is good.
  • You need instincts for scoping, context loading, verification, and when to interrupt the agent.
  • You also need instincts for when the context window has drifted and the best move is to reset, split, or reframe the task.
  • You get better at choosing between interactive work, delegated work, and parallel work.
  • You also get better at deciding what belongs in a markdown file, a settings file, or a reusable skill.
  • The best practices are real, but fluency only comes from repetitions.
What practice changes

The better you get, the less you ask for “AI help” and the more you design a loop

  • Better prompts become better task definitions
  • Better repo instructions change behavior, not just describe structure
  • Better context discipline means fewer long, drifting sessions
  • Better permissions mean fewer boring approvals
  • Better taste means better decisions about what not to ship
